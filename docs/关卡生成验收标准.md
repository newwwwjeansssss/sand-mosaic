# 原创关卡生成验收标准

适用范围：我们的 1–50 关及后续原创关卡。保留独立列表、竞品对照、多种沙盒位置与池内多色设计。该标准补充此前“布局多样、有解、供需平衡”的检查，不能用此前的通关记录代替本标准。

## 1. 玩家操作前保持静止

- 进入试玩后，未发生有效移动时，不吸沙、不完成消除。
- 自动检查新关卡静置 30 秒：已收集沙量、方块填充量、完成层数均不变。
- 点击、选中方块、尝试无效移动不应启动吸沙；有效移动后才进入正常模拟。
- 另查首次有效移动是否带来未计划的其他方块吸沙、消除，防止靠启动条件掩盖开局摆放问题。

## 2. 先设计前三次消除，再安排初始摆放

- 用户已确认：**每完成一层算一次消除**；不要求整个多层方块消失。全关不足三层时检查全部层数，第 1 关检查两次。
- 每关明确 A → B → C 的方块 ID、层号和颜色，并写明每一步解除哪项阻碍、为什么其他方块不能先完成。
- 优先使用方块相互占位、狭口、可用接沙边缘、颜色接触条件形成阻碍；冰冻、方向限制、钥匙等只在已引入的阶段使用。
- 可以让其他方块先移动让路；必须限制的是消除顺序，不是强制每次拖动的对象。
- 部分吸沙也可能产生绕过路径，要纳入状态判断，不能只比较方块起点到沙池的距离。
- 找到一条 A → B → C 的回放只证明该顺序可行。还必须检查所有其他可能的首消，以及 A 后、A → B 后是否能抢先消除其他层。
- 有限搜索没有找到反例，不等于证明唯一顺序；超出搜索预算的关卡标为“待验证”，不能通过验收。同时发生的多次消除也不能当作玩家经历了明确的三个先后步骤。

## 3. 难度采用有解释的移动成本

每关至少记录：前三次消除各自新增的移动格数、拖动操作数、让路操作数，以及全关对应总数。

- 移动格数：方块水平或垂直移动 1 格计 1 格。
- 拖动操作数：实际输入的一次按下到松开计 1 次；自动回放没有按下/松开信息时，只报告“连续同向移动段数”，不冒充实际手势次数。
- 连续同向移动段：同一方块连续同向移动为一段，换方块、转向、反向或等待后重新移动另计一段。
- 必要让路操作：为了后续方块抵达接沙位置而移动其他方块的步骤；须有路径或阻碍证据，不能把解算器随机挪动都算成设计难点。
- 通过完整最短路搜索的指标标为“最少”；只找到通关路径时标为“已验证解的步数上界”。不能把上界当最少步数，也不能把自动模拟时长当玩家完成时长。
- 难度曲线结合经验证的移动成本、顺序约束、可用空间与新机制理解成本。教学关保持较低操作成本；新机制出现后安排练习，再安排组合挑战与缓和关。
- 现有编辑器的 1–10 分为布局/机制静态估分，尚未计入最短移动成本；不得将它称为本标准下已确认的难度。

## 4. 保持紧凑，保留有用途的空间

- 分别统计棋盘格、沙池格、墙格、方块占格和初始可用空格。方块密度 = 方块占格 ÷（棋盘格 − 沙池格 − 墙格），不能靠多放墙虚增紧凑指标。
- 保留转身、交换、错位和临时停车必须的空格；其他空白优先通过缩小棋盘或重排结构减少。
- 每个疑似多余区域都要检查删去后能否完成目标顺序和整关通关；一条回放没有经过的格子只能标为“待评估”，不能直接认定无用。
- 减少空格后重新检查布局、前三次顺序、供需和完整通关；不能为了密度引入死局。
- 紧凑度服务于移动决策与关卡轮廓，不把全部关卡收敛成同一个排队通道模板。

## 发布门槛

四项分别记录“通过 / 不通过 / 待验证”，只有全部通过才可称为符合新标准。每关保留与最终 JSON 哈希一致的回放和检验结果。竞品 577 关不变；重制数据在独立候选区验收后再替换我们的列表。

原定玩法引入位置继续保留：8 关冰冻、16 关方向限制、26 关多层盒、40 关锁钥匙、50 关管道。任何重新规划应明确说明原因，不能为了强制顺序偷偷提前加入后期机制。
